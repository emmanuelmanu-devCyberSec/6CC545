9. TCP LENGTH PREFIX AND UDP DATAGRAM
============================================================

TCP framing:
TCP provides a byte stream and does not preserve application message boundaries. The implementation uses a four-byte big-endian length prefix to indicate the number of bytes in the next message. The receiver reads the frame according to the declared length and can reject oversized frames before processing them. Incomplete headers, incomplete bodies and timeouts must also be handled.

UDP datagrams:
UDP preserves message boundaries as separate datagrams. The receiver validates each datagram's size directly rather than relying on TCP-style stream framing. UDP does not guarantee delivery or ordering, so a sender cannot assume that every transmitted datagram will arrive.

Result:
PASS. The successful TCP and UDP messaging tests confirmed that both transports exchanged messages and returned acknowledgements. The protocol tests verified relevant framing and failure-handling behaviour.
